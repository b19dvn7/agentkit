How to write a CLAUDE.md that actually controls your AI coding agent

Most CLAUDE.md / AGENTS.md / .cursorrules files are either empty or a wall of vague platitudes the agent ignores. A good one is the single highest-leverage thing you can do to make Claude Code, Cursor, or Copilot behave. Here's how to write one that works.

The mental model: context economy

An agent has a finite attention budget and no memory of your project between sessions. Your config file is persistent, high-priority context — the things you'd otherwise repeat in every conversation. The test for anything you put in it:

  • Would I have to say this again next session?
  • Does saying it once prevent a whole class of mistakes?

If yes, it belongs. If it's a one-off, it doesn't. A bloated config buries the rules that matter, so optimize for signal, not coverage.

The 3-section minimum

Every useful config needs these three, in priority order. Everything else is polish.

1. Commands

How to install, run, test, and lint. Without these the agent literally cannot verify its own work — and an agent that can't verify will confidently tell you broken code is done.

2. Gotchas

The three to six things specific to your codebase that break if mishandled. This is the highest-value section and the one almost everyone skips. "Don't call blocking I/O inside an async route." "Migrations for every model change — never touch the DB by hand." "Memoize props or the list re-renders." Specific, stack-aware, hard-won.

3. Behavior

The universal guardrails that stop the most common failures:

  • Do only what's asked — surface ideas, don't silently act on them
  • Read before you write; match existing patterns
  • Small, focused diffs — don't reformat unrelated lines
  • Verify before claiming done — show the test output
  • No destructive commands without confirming impact first

A worked example

A minimal but real config for a TypeScript API looks like this:

  • Commands: npm install · npm test · npm run lint · tsc --noEmit
  • Gotchas: "No any — narrow from unknown." "Centralized error middleware; wrap async handlers." "Validate request bodies at the boundary."
  • Behavior: the five guardrails above.

The mistakes that make configs useless

  • Vagueness. "Write good code" does nothing. "Run tsc --noEmit before saying done" does.
  • Bloat. 600 lines and the agent drowns. Cut to signal.
  • Product backstory. The agent doesn't need your funding history — it needs your test command.
  • Set-and-forget. When the agent makes a preventable mistake, add (or sharpen) one rule and delete a stale one. Treat the config as code: version it, review it, revisit it.

Per-tool notes

  • Claude Code: CLAUDE.md at repo root (nested files allowed in monorepos). Saying "these override default behavior" carries weight.
  • Cursor: .cursorrules at root, or scoped .cursor/rules/ files.
  • Copilot: .github/copilot-instructions.md.
  • Generic / multi-tool: AGENTS.md. The content is ~95% identical across tools — port with a rename.
